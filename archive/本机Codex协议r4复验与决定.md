## 3. 三个需要修复的复现问题

### F1 已上报的执行终态会被矛盾结果改写

位置：refimpl/render_protocol/statemachine.py 的 JobTracker.on_result。

复现：同一尝试先通过 on_status 上报 cancelled，再通过 on_result 上报 succeeded。实际返回 accepted，最终显示 succeeded。

需要：结果与已记录的执行终态必须一致。没有中间状态时仍可接受合法结果；已经有执行终态时，矛盾结果应明确拒绝或冲突，不应覆盖。测试覆盖 cancelled→succeeded、succeeded→failed、failed→succeeded，以及相同终态结果正常接受。

这不否定“允许向前跳跃”；向前跳跃与终态互相矛盾是两回事。

### F2 job.json 不可用时仍要求知道计划帧数

位置：schemas/result-v1.schema.json 的 frames.expected、semantics.check_result 的 XF-R15，以及 result.job_unreadable.json。

该样例允许 bundle 和 adapter 为 null，却填入了 expected=3。真实场景中 job.json 无法读取或解析时，Worker 不知道计划帧数。把 expected 改成 0 会返回 XF-R15；填 null 当前也不满足 schema。

需要：仅对 failed + validation_error + phase_reached=validate 且任务定义不可用的分支，允许 expected=null，rendered=0，并在此分支跳过计划帧数比较；其他分支保持强校验。不要要求 Worker 猜测。另明确 attempt_id 与账本应在下载失败上报之前建立，当前 6.3 把创建尝试放在校验成功后。

### F3 任务包重复路径和目录大小写别名未拒绝

位置：refimpl/render_protocol/bundle.py 的 check_paths。

已复现两个输入都返回空错误列表：

1. 两个同名普通文件 scene.js（重复 tar 条目）。
2. Scene/a.js 与 scene/b.js（隐式父目录大小写不同）。

第一个会产生覆盖和提取器行为差异，第二个违反双方约定的 Windows/Linux 一致路径规则。请对普通文件完整路径拒绝精确重复，并对每一级显式及隐式目录建立统一大小写映射。允许常见的“先由子文件隐式创建目录、后出现同名显式目录条目”，但不能允许大小写不一致。

增加实际 tar 输入测试，不只测试路径列表，确保提取前就拒绝歧义。

## 4. 六项设计决定的明确答复

| 项目 | 本机意见 | 实施约定 |
|---|---|---|
| 状态可向前跳跃 | 同意 | 仍检查合法枚举、序号、进度和结果一致性，不能跨终态改写 |
| retry_scheduled | 同意 | 保留错误类别和尝试上限约束；取消在 retry_pending 期间发生时，明确取消剩余重试且收敛到终态，补一个测试 |
| 隐私隔离即终态 | 同意 | 无自动重试，后续修正作为新任务，保留追溯关系 |
| 禁止浮点 JSON 数值 | 同意 | 小数参数以字符串传递，场景或适配器明确解析、范围及非有限值处理；小数字符串的不同写法可视为不同输入，无需额外规范化 |
| 结果 worker_lost 指进程中断 | 接受 v1 命名 | 文档和用户界面明确区分执行中断与网络失联；网络断开不得触发执行重试 |
| 重启不接管残留渲染 | 同意 | 只终止可验证属于该任务的进程树，不能仅凭可能复用的 PID；确认停止后才重试。已完成且结果落盘的任务应恢复交付，不重新渲染 |
