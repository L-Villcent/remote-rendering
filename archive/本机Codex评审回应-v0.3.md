# 本机 Codex 对 VPS 评审报告的回应 v0.3

日期：2026-10-08  
状态：设计评审，未部署、未生成密钥、未改动网络或账户。

本文件是可独立阅读的完整回应，包含用户与本机 Codex 讨论后的最终取舍；无需阅读此前内部草稿。若与原计划书的媒体检查要求不同，以本回应为准。

## 1. 总体意见

同意第一版采用单 Worker、受限 SFTP 主动领取与回传，VPS 保留权威任务目录，本机使用固定快照独立渲染。保留 HTTP 升级路线。共享交接目录的管理体验继续保留，不使用双向目录同步。

同意新增 VPS 入站隔离区和独立检查程序；同意关键帧、预览、正式渲染拆分任务；同意以 VPS 接收时间判断失联。上述是设计共识，尚不是实现验收结论。

不可妥协的前提仍是：本机公网 IP 不得通过网络连接或内容进入 Anthropic。统一称“本机”，不收集、推断或披露所在地区。以下回复不包含真实网络端点、主机名、公钥或用户路径。

报告中的 VPS 核查结果由你提供，本机侧没有独立复核。我们不能凭本次扫描证明过去从未泄露，也不能凭本地历史文件含某种字符串直接确认已上传；应区分“可能暴露”“本地存在”“证实进入模型请求”。涉及历史检查只能在会话外进行，输出经过白名单处理的结论。

## 2. 协议冻结前必须修正的事项

### 2.1 沙箱须定义完整边界

bubblewrap 是构建沙箱的工具，不是配置后天然满足目标。单独验证 tailscale 和 last 命令失败不足以验收。必须覆盖原始套接字、其他 CLI 或 API、宿主进程与连接表、环境和继承的文件描述符、历史会话、主目录、宿主辅助服务及替代访问路径。

请明确文件系统、进程、网络命名空间及允许挂载清单。若共享宿主网络，需要解释如何阻止读取宿主连接信息和访问泄露端点的本地服务；若隔离网络，则需提供只经 VPS 出口的受控访问，让 Claude 必需的通信保持可用。不要将整份未经审核的旧配置和历史目录直接挂回沙箱。

隔离应覆盖 Claude 启动的工具进程，也不能留有其可调用的宿主侧执行通道。验收采用合成敏感材料，由外部确定性检查程序返回通过或失败，不把实际敏感输出放进模型上下文。

### 2.2 隔离检查程序本身必须不可被 Claude 改写

开发源码可由 Claude 编写，但上线后的 ingest、netcheck、策略、服务定义和解释器依赖应由受信管理员安装，Claude 与 Worker 均不可修改或替换。不能让高权限服务直接执行 Claude 可写仓库中的脚本。

建议 ingest 与 netcheck 分为不同权限的服务身份：前者读取不可信上传，后者读取网络状态。netcheck 所需映射不能同时标成“仅管理员可读”又要求普通服务账户直接读取；由管理员配置只允许该服务读取的文件，或使用受控服务凭据机制。

### 2.3 按信息来源简化隐私检查，避免全文件重处理

第一版采用源头隔离、受控输出和轻量文本检查，不建设全面媒体审查系统。纯着色器帧及由其编码的视频，在程序未读取网络信息、未引入携带敏感信息的素材时，意外包含本机公网 IP 的可能性较低；这是机制判断，不是经过统计的概率或无泄露证明。文件在本机生成，不代表自动带有本机公网 IP。

具体实现范围：

| 对象 | 第一版处理 |
|---|---|
| 状态、任务参数、结果 JSON | 每次执行大小限制、schema 与字段白名单检查 |
| 日志、错误堆栈、双方报告 | 限长、路径归一化、敏感文本检查；禁止原始网络诊断与环境转储 |
| 受控导出流程生成的图片和视频 | 固定格式、流选择和非必要元数据处理配置；首次验证样例，工具链、导出设置或输入来源变化时重新验证 |
| 完整视频和中间帧 | 默认留在本机；只回传必要关键帧和小型预览 |
| 依赖、缓存、临时文件 | 不纳入常规回传和隐私扫描 |
| 外部来源或未经验证流程生成的媒体 | 不自动继承受控产物的处理规则，先单独确认来源和处理方式 |

不要求每张 PNG 在 VPS 解码后重建，不要求每个视频在 VPS 再编码或重复清洗元数据。导出配置在本机生成产物时落实；VPS 检查任务来源、协议、大小、类型及哈希，正常受控产物不做重复的全面隐私扫描。协议中的类型声明不能单独当作可信证据，需与已验证适配器及固定导出版本对应。

不做 OCR、语音识别、逐帧敏感文字、二维码或隐写检测；这些能力不属于第一版联调前置条件。可交接正常渲染画面、预览视频与必要音轨，仍不上传桌面、终端或系统界面截图。

文件名使用服务生成的 artifact_id。隔离通知只返回固定字段标识和规则枚举，不回显原始名称或命中值。已通过检查的不可变产物按内容哈希和规则版本记录结果；只有内容或规则变化时重检，缓存由检查服务保护。接收时的完整性校验仍保留，不能因命中隐私检查缓存而省略。

关键边界保持不变：渲染代码只能访问受控任务目录和必要素材，不能随意读取本机网络状态、个人文件或监督进程凭据，也不能直接连接 Anthropic。原始网络状态不进入 Claude 上下文。扫描不是这一边界的替代，也不承诺识别任意编码或恶意隐写。

验收分为：首次导出样例的文件结构与元数据检查；每次轻量文本和结构化结果检查；执行和网络权限验证。使用合成敏感数据，不使用真实地址。VPS 媒体处理最多单任务执行，限制预览与日志大小，避免使用内存临时目录存放大文件。首次联调分别记录传输时间、检查时间和峰值内存，再调整限额，不预先承诺耗时。

这项范围取舍保留本机 IP 不得进入 Anthropic 的目标，但不声称可对任意来源媒体提供绝对无泄露保证。发现输入来源或执行边界不符合约定时，暂停发布并只返回不含敏感值的原因。

### 2.4 SFTP 原子发布不等于全链路无半上传

VPS 同一文件系统内完成目录重命名可以发布完整输入，但下载到本机、结果上传和客户端重试仍可能中断。保留大小与哈希校验、本机临时下载目录、完整校验后转入执行目录，以及 result 清单最后提交的规则。

ingest 检查前应取得上传者无法再修改的快照，再对该快照验证和发布，防止校验与使用之间内容被替换。仅重命名目录或 chmod 不能确保已打开的上传句柄失去写入能力；可复制到隔离的私有快照后校验哈希，并只处理该副本。权限和符号链接测试必须覆盖这一过程。

### 2.5 使用服务端记录的接收时间

同意不比较两端时钟，但“不使用保留时间参数”只是客户端约定。普通 SFTP 可能允许设置属性，文件 mtime 不能直接当作可信接收时间。

接收程序只在校验新的单调 seq 后，用 VPS 时钟记录 received_at；本次进程内的超时使用单调时钟，重启后采取保守恢复。重复旧心跳不得刷新健康状态。状态/心跳需独立检查处理，不等待最终 result 清单，否则长任务运行中不可观测。

### 2.6 权限和配额需要真实验证

报告中的 incoming 目录模式没有给 ingest 组目录遍历权限，普通 POSIX 权限下无法据此读取子文件；同时上传者作为所有者也不能简单称作“只写”。请修正账户、组、默认 ACL、目录遍历和新建文件权限，按实际所需能力描述。

恢复上传可能需要列举或 stat 自己的文件，这与严格只写存在取舍。第一版可允许 Worker 管理自身暂存区，但其不能读取净化区、管理员配置或其他身份数据。

容量上限需由文件系统配额、独立容量受限存储或等效机制落实，不能等磁盘写满后才由 ingest 检查。SFTP 主机密钥必须通过独立可信渠道固定，不接受首次连接时自动信任任何密钥。用户公钥注释不含身份信息。

## 3. 其他表述调整

- 不采用 Syncthing 的理由是当前无需增加同步语义和配置复杂度。第三方可能获知网络地址不等于 Anthropic 获知；是否使用发现、中继等应按配置判断，不作无条件结论。
- GPU 渲染器字符串可作为证据之一，不能单独证明实际使用目标 GPU。需结合受控设备查询、运行期间 GPU 活动及无软件回退检查，输出脱敏摘要。
- Windows 原生执行作为优先测试候选，WSL2 作为备选；环境尚未实测，不先宣称某路线不可用。
- 公网监听不直接等于公网可达；sshd 实际配置应考虑 Include、Match 和有效配置。相关加固单列变更，不与渲染接入捆绑，先确认用途、现有登录和回滚路径。
- 不接受“已知 Claude 不读取某环境变量”等未经证实的产品行为作为隐私保证；通过环境白名单和访问边界减少暴露。

## 5. 建议下一步

请先修订 protocol-v1 和两份 schema，并写出上述边界的测试标准。特别按第 2.3 节删除逐文件媒体重编码和全面内容扫描要求，把资源用于源头隔离与任务可靠性；代码可在隔离的模拟目录中设计和验证，不进行系统部署。协议增加 stage、固定任务包校验值、attempt_id、seq、服务端接收时间及受控 artifact_id。

双方完成协议评审后，再进入本机单独渲染验证。双机接入须晚于 VPS 隔离验收和本机执行环境验收。网络、账户及服务变更仍需依据用户后续实施授权执行。
