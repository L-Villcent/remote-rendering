# VPS Claude 与本机 Codex 渲染协作计划书

日期：2026-10-08  
版本：0.2，加入共享交接目录与强化隐私前提，供双方评审  
收件人：运行在德国 VPS 上的 Claude Code  
编写方：用户 Windows 本机上的 Codex

## 1. 给 Claude 的说明

用户希望你继续在德国 VPS 上编写代码、组织项目、调用 Anthropic，同时能够调用用户本机的 CPU、内存和 GPU 完成视频、着色器及后续其他重计算任务。我负责本机执行端，你负责 VPS 调度端。用户会转交本文件并在初期传递双方报告；目前我们没有已经建立的直接跨端协作通道。

本轮交付是设计计划，不表示两端服务已经部署，也不表示用户已要求立即修改系统网络或账户。请先检查你所在 VPS 的实际环境，审阅协议，返回第 12 节要求的交接报告。不要仅凭本文宣称本机已连通或安全边界已通过验证。

我们共同的交付目标是：你提交一份带版本标识的渲染任务，本机自动执行并返回日志和关键帧；你能根据结果修改代码再提交，最终得到视频。日常任务执行不依赖本机 Codex 聊天持续在线。

## 2. 已知条件和边界

**不可妥协的前提：本方案不得将本机公网 IP 暴露给 Anthropic，包括网络连接来源，以及模型可读取的工具输出、文件、日志、截图或其他内容。全文统一称为“本机”，不收集、推断或披露本机所在地区。该条是必须验证的验收要求，不是已实现的保证；无法确认满足时不得宣称方案通过。**

- 原始文档描述：德国 VPS 为 2 核、2 GB RAM，已配置 swap；Claude Code 和 VS Code Server 位于 VPS；现有连接使用 Tailscale 与 SSH。这些 VPS 状态需要你复核。
- 本机为 Windows。此次只读检查发现 ssh、wsl、tailscale、nvidia-smi 可执行文件；这不证明发行版、GPU 或 Tailnet 已正常工作。
- 硬件查询被当前访问权限拒绝。CPU、RAM、GPU、显存、磁盘余量、驱动及渲染软件版本待核实。
- Claude 主进程、Anthropic 凭据及与 Anthropic 的连接留在德国 VPS。本机 Worker 不安装或登录 Claude，不存储 Anthropic 凭据。
- 本机执行环境不得默认访问用户个人文件、浏览器数据和主账户私钥。
- 本机离线时，GPU 任务排队或返回明确不可用；不得静默回退到 2C2G VPS。
- 本项目 sources/ 下的同步参考文件只读，不编辑或移动。

## 3. 推荐架构

采用本机主动领取任务的轻量队列。新增建议是第一版优先评估“共享交接目录＋任务清单＋本机 Worker”，保留原有 HTTP 任务服务作为备选及扩展路线，请 VPS Claude 独立评审。两种实现共用任务编号、清单和结果协议。VPS 保存任务输入和小型反馈，本机负责渲染、编码及大文件存储。

```text
用户 → VPS Claude → renderctl → 共享交接目录（或任务服务）
                                   ↑           ↓
                          本机主动连接、领取与上报
                                   ↑           ↓
                             本机 Worker 监督进程
                                   ↓
                         受限的逐任务执行环境
                                   ↓
                     本机 GPU 渲染 → 帧序列 → 视频
                                   ↓
                 日志、关键帧、预览片回传；完整视频按需传输
```

Tailscale 提供私网连接，传输账户或应用认证负责限定 Worker 身份。第一版可让本机通过 Tailnet 上的受限 SFTP 账户定期领取 VPS 交接目录中的任务并回传结果，不必开放本机入站服务。也可评估定向同步软件，但需验证连接路径、冲突和完整性，不默认引入第三方云盘。若目录方案不能满足需求，再采用单进程轻量 HTTP 服务、SQLite 状态库和文件目录；服务只绑定 Tailnet 接口或通过受控隧道访问，不默认开放公网。无需 Redis、Kubernetes 或独立消息中间件。

本机监督进程在后台保持运行，主动连接 VPS 获取任务。实际渲染子进程不持有 Worker 认证材料。任务持久化，连接断开不会直接终止渲染。

与 SSH 直接执行相比，这个设计多了一层任务状态管理，但更适合本机随时开关机、分钟到小时级渲染、结果重传及未来增加计算节点。必要时可用 SSH 做初期连通性诊断，但不以交互会话作为正式任务生命周期。

## 4. 两端分工与交付物

| 工作 | VPS Claude | 本机 Codex |
|---|---|---|
| 环境核查 | 系统、资源、Tailnet、现有服务与端口 | 硬件、GPU 后端、权限、工具链与磁盘 |
| 协议 | 编写目录发布与查询端、renderctl 与协议测试；必要时升级服务 | 按同一协议实现 Worker |
| 源码 | 保存主副本，产生不可变任务包 | 校验、解包并执行，不修改主副本 |
| 渲染 | 编写场景、着色器及导出要求 | 安装经确认的运行环境、实现渲染适配器 |
| 隔离 | 限制服务访问及令牌权限 | 隔离文件、凭据、子进程及公网访问 |
| 联调 | 提交任务、检查反馈、修改后重试 | 验证真实 GPU 执行、故障恢复与产物 |

双方共同维护 protocol-v1.md、任务与结果 JSON Schema、一个示例任务包和验收记录。初期通过用户转交文件及报告；建立连接后由程序交换任务数据。双方 AI 聊天不会因此自动互通。

## 5. Claude 可使用的接口

以下为拟定接口，不是已安装命令：

```text
renderctl workers
renderctl submit <manifest.json>
renderctl status <job_id>
renderctl logs <job_id> --tail 100
renderctl artifacts <job_id>
renderctl fetch <job_id> --kind preview
renderctl cancel <job_id>
```

提交立即返回 job_id；Claude 后续查询，无需保持终端阻塞。第一版使用命令行即可，MCP 可在协议稳定后作为包装层添加。

目录方案以任务清单、领取记录、心跳、取消请求和结果清单表达状态；若升级 HTTP，则映射为 Worker 注册与能力上报、任务领取、心跳续租、进度更新、产物上传与完成确认。所有写操作检查认证和任务归属；管理和取消权限与 Worker 权限分离。第一版限定唯一 Worker，并通过本机排他锁及持久执行账本防止重复执行；不得把两端各自的同步文件重命名当成跨机器原子锁。增加多个 Worker 前，必须实现权威端原子领取。

任务清单示例：

```json
{
  "protocol_version": 1,
  "idempotency_key": "demo-shader-v1-preview",
  "project_id": "shader-demo",
  "source_sha256": "<任务包校验值>",
  "adapter": "webgl-frames-v1",
  "entrypoint": "scene/index.html",
  "render": {
    "width": 1280,
    "height": 720,
    "fps": 30,
    "frame_start": 0,
    "frame_end_exclusive": 150,
    "seed": 42
  },
  "limits": {"timeout_seconds": 600},
  "network_policy": "offline",
  "artifacts": ["logs", "contact_sheet", "preview_mp4", "final_mp4"]
}
```

示例参数用于首次验证，实际任务由资源预算决定。清单还需关联适配器版本及工具链版本。adapter 必须来自已安装列表，entrypoint 必须是任务目录内的相对路径；不提供任意管理员 shell 接口。

结果需包含 job_id、attempt_id、状态、退出码、错误分类、源码哈希、工具链版本、实际渲染设备、帧数、耗时和产物清单。每项产物记录大小、SHA-256、保存位置、是否已上传；绝对本机路径不冒充可在 VPS 下载的地址。

## 6. 状态与可靠性

任务状态：queued → leased → running → uploading → succeeded；另有 failed、cancel_requested、cancelled。完成必须等所需小型反馈上传成功；完整视频若选择留在本机，要明确标注本地保留状态。

- 第一版仅允许一个 Worker、一个活动 GPU 任务，先保证正确性。
- 心跳、租约和 attempt_id 区分同一任务的不同执行尝试。租约过期后标记失联；第一版不自动把同一 GPU 任务分配给其他 Worker。重试需确认旧执行已停止；晚到结果不能覆盖新尝试。
- 重复提交使用幂等键去重；同键不同内容返回冲突。
- 网络中断时本机继续渲染并把待上报结果落盘，重连后重传。
- 取消先记录请求；Worker 在线后终止完整子进程树，再确认 cancelled。离线时不能假报已停止。
- 任务超时、磁盘不足、显存不足分别返回明确原因。失败重试有次数上限。
- Worker 重启后核对记录和残留进程，不把旧 running 状态当成仍在运行。
- 日志截断、滚动保存；磁盘配额和保留期限明确。清理只作用于已验证的任务根目录，不删除项目主副本。

## 7. 渲染执行机制

第一目标建议采用程序化着色器动画：固定随机种子，显式设置每帧时间 t = frame_index / fps，等待素材和 GPU 输出就绪后导出图像，最后在本机编码。5 秒、30 fps 对应帧编号 0 至 149。不要依赖实时录屏的播放速度决定视频时间。

第一步先生成关键帧，再导出低分辨率预览，最后正式渲染。Claude 获取联系表或独立 PNG 检查画面；若 VPS 会话不能读取图像，应明确报告能力缺口，由用户查看，不把退出码当成视觉验收。

浏览器渲染、Blender、其他原生程序分别实现适配器。第一版只支持一种已验证适配器，不承诺任意代码均可远程 GPU 加速。GPU 渲染和视频硬件编码是不同环节，分别核实；编码器可用并不代表着色器或三维渲染用了 GPU。

WSL2 与 Windows 原生执行的选择由真实小样测试决定。WSL 的某类 GPU 计算支持不代表所有图形 API 均可用。若 WSL 图形路径不能稳定使用目标 GPU，可选择独立 Windows Worker 账户及相应限制；不能为方便而使用日常主账户和其完整权限。

## 8. 文件与资源策略

### 8.1 共享交接目录建议

“共享”指两端能通过受控传输访问同一套交接文件，不要求相同绝对路径，也不要求渲染程序直接读写远程磁盘。推荐结构：

```text
exchange/
  handoff/vps/       VPS Claude 发布报告，本机读取
  handoff/local/     本机 Codex 发布报告，VPS Claude 读取
  jobs/<job_id>/     VPS 发布固定任务包与输入清单
  control/<job_id>/  VPS 发布取消等控制请求
  results/<job_id>/  本机发布状态、日志、关键帧与预览

本机独立目录（不整体同步）/
  runs/             每次任务的固定输入与执行现场
  cache/            素材、工具链及依赖缓存
  exports/          完整视频与大型产物
```

每类文件只有一端负责写，另一端只读。报告以版本化文件发布，避免双方编辑同一文件。目录 ACL 或传输接口落实这些权限。共享范围仅限专用交接根目录，不能共享个人主目录。

发布时先写临时文件，完成后在发布端重命名；输入清单记录文件大小、SHA-256、版本和参数。本机即使先看到 ready 标志，也必须等待全部文件到达并校验成功，才能解包到独立 runs 目录执行。单个文件的完整写入不能保证整个目录已同步完整。

Worker 渲染固定快照，Claude 后续修改以新任务发布。结果也先生成、校验和脱敏，再发布清单；状态更新带递增序号，忽略晚到旧状态。断线后按 job_id、attempt_id 和校验值续传，不重复启动同一任务。

不共享运行中的 SQLite 数据库、锁文件、凭据、node_modules 或渲染临时帧目录；取消通过独立控制请求表达，不通过删除任务目录触发。同步不是备份，删除传播和保留策略须明确，源码另由 Git 管理。

handoff 目录可减少用户搬运双方报告的工作，但文件到达不会自动唤醒已结束的 AI 会话；无人值守执行由 Worker 完成。任何进入 Claude 可读目录的材料必须先经过第 9 节的隐私检查。

请 Claude 比较“受限 SFTP 领取与回传”“定向目录同步”“HTTP 服务”三条路线，说明复杂度、权限、完整性和恢复机制，再与本机 Codex 冻结第一版实现。

### 8.2 本机执行与缓存

主源码由 VPS 管理。每个任务发送固定快照和校验值，素材按内容哈希缓存；VPS 的 Linux node_modules 不直接复制成 Windows 运行环境。依赖按锁文件在选定运行环境准备，预置稳定工具链，避免每次安装。

本机每个任务拥有独立 input、work、output、logs 目录。解包防止路径穿越、越界链接和异常大文件。渲染期间不覆盖输入快照。必要时把帧序列作为恢复检查点，但仅在版本、输入和参数完全一致时恢复。

完整帧序列和视频优先保留本机；默认向 VPS 回传截断日志、关键帧、产物清单及小型预览。1080p RGBA 原始像素每帧约 8.29 MB，30 fps 时 20 秒约 4.98 GB，说明逐帧跨网传输不合适；实际压缩体积取决于内容。

限制同时运行数、任务时长和磁盘占用。GPU 显存通常无法像普通任务参数一样任意硬限制；需使用分辨率、场景规模、并发控制和监测处理。预留用户日常使用资源，具体额度待硬件核实。

## 9. 网络与文件隔离

### 9.1 本机 IP 与地区信息不得进入 Anthropic

此要求同时覆盖两条路径：本机不得直接向 Anthropic 建立连接；本机公网 IP 及地区信息不得作为内容进入 Claude 的上下文或被上传至 Anthropic。仅将 Claude 部署在 VPS 并不足以满足第二条。

- VPS 上的 Claude 不得直接读取原始 Tailscale 状态、连接端点、网络诊断、访问日志或抓包输出，这些内容可能含有本机公网 IP。诊断由本机侧或隔离的确定性检查程序处理，只向 Claude 返回允许的摘要，例如“可达”“直连/中继”“校验通过”，使用 worker-local 等别名。
- 不查询本机公网 IP、IP 地理位置或地区信息来编写交接报告。必须验证出口时，由确定性程序在模型上下文之外比较出口是否等于预先配置的 VPS 出口，仅返回通过/失败；不回显本机地址。
- 同步任务输出前执行字段白名单及敏感内容检查。错误堆栈、网络错误、截图、视频元数据、文件名和报告同样纳入范围；原始网络日志不进入 handoff、results 或 Claude 可读工作区。
- 监督程序所需网络地址和认证配置与模型可读材料分离，由操作系统权限限制访问。若 Claude 的运行身份仍可读取含本机 IP 的底层日志或配置，就不能宣称已满足“不可读取”的边界，须调整账户和权限。
- Tailscale 等传输组件可能需要处理节点网络端点；这不等于 Anthropic 获得该信息，但相应日志不能被原样交给 Claude。同步工具的发现、遥测和其他出网行为也需纳入网络审查。
- 验收使用合成敏感信息测试脱敏、权限和上传拦截，不把真实本机 IP 粘贴给 Claude 让其判断。边界不明确时停止相关上传并报告不含敏感值的失败原因。

### 9.2 执行与出网限制

本机监督进程只需连接受控 VPS 端点；渲染进程默认禁止公网访问，必要的本机回环通信单独允许。依赖准备与渲染执行分开，不能把 npm 安装脚本等视为无害下载。

确实需要联网时，经验证的德国 VPS 出口访问，并在出口失效时阻止直接联网。单纯 HTTP_PROXY 环境变量不构成强制边界；域名黑名单也不作为唯一控制。验证 IPv4、IPv6、DNS 和实际应用进程路径，避免只查询一次出口 IP 就宣布通过。

WSL 默认具有 Windows 盘符挂载和互操作能力。独立发行版或用户不是完整安全保证；需要限制自动挂载、互操作、提权能力、目录权限及实际可达资源。Windows 原生 Worker 同样需要独立非管理员账户和目录 ACL。采用哪种沙箱须做访问测试，不以名称判断隔离程度。

Worker 令牌保存在监督进程可读位置，不放入任务包或子进程环境。日志输出限于任务内容，避免夹带本机公网地址、环境变量、令牌和个人路径。德国出口控制连接来源，不保证请求内容绝不会携带本机信息。

## 10. 实施阶段与验收

| 阶段 | 工作 | 完成标准 |
|---|---|---|
| P0 环境确认与协议冻结 | 双方提交脱敏报告，比较目录与服务方案，确定适配器、隔离和接口 | 两端认可 protocol-v1，未确认项明确标注 |
| P1 本机独立渲染 | 本机运行 5 秒样例，先关键帧后视频 | 输出 150 帧及 5 秒视频，证据表明渲染使用目标 GPU |
| P2 双机任务链路 | VPS 提交、本机领取、结果回传 | 状态、哈希、日志、预览能对应同一任务版本 |
| P3 Claude 反馈循环 | Claude 查看关键帧，修改参数并重提 | 新版本画面发生预期变化，两次结果可追溯 |
| P4 故障与边界验收 | 断网、半同步、重复提交、失败、取消、权限、出网与内容隐私测试 | 未完整同步不执行，错误可恢复，个人目录不可达，禁止直连生效，本机 IP 与地区信息不进入模型可读材料 |
| P5 日常运行 | 后台启动、清理、暂停接单、使用说明 | 用户不需开着本机 Codex 聊天即可执行任务 |

不在第一版引入多机拆帧、大型调度平台或通用远程桌面。后续有第二台机器时，按适配器和设备能力调度独立任务；再评估可独立分帧的作业。需要跨帧状态的模拟不能随意拆分。
