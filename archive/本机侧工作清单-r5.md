# 本机侧工作清单（基线 protocol-v1 r5 / r5.1）

适用：本机 Codex。范围：在本机实现和验证；**不连接 VPS**。双机接入须等 VPS 隔离验收和本机执行环境验收都通过，并取得用户授权。
交接材料一律不含 IP、端点、主机名、地区或用户路径。

## A. 现在就可以做（不依赖 VPS）

| 序号 | 工作 | 依据 | 完成标准 |
|---|---|---|---|
| A1 | 确认 r5.1 补丁，并在本机运行 `tests\run_all.py` | VPS 回复 v0.6 | 各组通过；SCHEMA 组和 SL02 允许报告跳过 |
| A2 | 选定执行环境：先测 Windows 原生（独立的非管理员 Worker 账户），WSL2 作为备选 | 计划书第 7 节、安全文档 | 在小样上确认渲染器是目标 GPU（GPU-01） |
| A3 | `webgl-frames` 0.1.0 适配器：无头 Chromium；页面约定 `setup(params)` 和 `async renderFrame(i, t)`，其中 `t = i / fps`；从画布读取像素；固定随机种子 | protocol 6.4 | 同一输入渲染两次，帧逐字节一致（或明确记录不一致的原因） |
| A4 | GPU 证据：渲染器字符串经白名单归一化；受控设备查询；渲染期间的 GPU 活动；软件回退检测 | GPU-01 至 GPU-04 | 结果中的 `device` 字段如实填写，未知写 null |
| A5 | 固定导出流程：PNG（`png-rgb8-v1`）、预览 MP4（`h264-preview-v1`）、正式 MP4（`h264-final-v1`），用 ffmpeg 的 `-map_metadata -1 -fflags +bitexact`；联系表由渲染帧拼成 | protocol 第 7 节 | 导出参数固定并登记版本 |
| A6 | **MX-01 样例矩阵**：每个配置 3 种分辨率 × 2 种时长 × 2 种复杂度，另加 3 个矩阵外样例。可直接用包内的 `server/render_gates/mediacheck.py`（`describe` 和 `fingerprint`）生成结构摘要。摘要只含名称，不含值 | MX-01 | 把摘要和工具链哈希交给用户确认，作为正式登记表 |
| A7 | **P1 本机独立渲染**：5 秒、150 帧，先出关键帧，再出预览，最后出正式视频 | 计划书 P1 | 150 帧和 5 秒视频，并附 GPU 证据 |
| A8 | Worker 监督进程的本地逻辑：账本（先写后传）、排他锁、`worker_epoch`、**先建立尝试再下载**、下载重试 3 次、执行重试只按 `retry_scheduled` 规则、取消处理（排队中取消上报 `not_started`）、重启时只终止可验证属于该尝试的进程树（例如 Job Object）、已完成的尝试只补交付不重新渲染 | protocol 3、5、6.3、6.9、第 16 节 | 用本地目录模拟 `down/` 和 `up/` 跑通：参考包内的 `sim/fake_worker.py`（它只是测试驱动，不是可以照搬的实现） |
| A9 | 本机侧校验：严格 JSON 解析；schema 校验（可以复用 `minischema.py`）；在 Windows 上执行 XF-J 和 XF-B 规则，`bundle-path-vectors.json` 中每个用例结果一致；上传前对结果做 XF-R 自检 | PR-15、PR-16 | 测试向量全部通过 |
| A10 | 本机第一道隐私防线：文本规则（可以复用 `textrules.py`）、路径归一化为 `<task>/…`、日志只用 UTC 或相对时间、不发送墙钟时间、不做环境转储 | protocol 第 8 节、3 | TX 语料在本机得到相同结果 |
| A11 | 隔离：渲染子进程禁止联网，不能访问个人目录，不持有 Worker 凭据；监督进程只能连到 VPS 的 Tailnet 端点 | PV-01、PV-02、安全文档 | 使用合成金丝雀测试，只输出 PASS/FAIL |
| A12 | 上传的实现：文件先上传为 `.part-` 临时名再用 posix-rename 改名，result.json 最后上传；心跳使用**单独的连接**；产物上传限速；按确认结论清理或重传 | protocol 6.5、6.6、5.2 | 先用本地目录模拟验证；接 SFTP 要等部署阶段 |

## B. 部署阶段才能做（需要用户授权）

| 序号 | 工作 | 验收 |
|---|---|---|
| B1 | 生成 Worker 的 SSH 密钥（ed25519，注释中不含身份信息），**公钥**经用户转交 | FS-05 |
| B2 | 固定 VPS 主机密钥：指纹由用户在独立终端读取，经可信渠道写入 known_hosts，`StrictHostKeyChecking yes` | FS-07 |
| B3 | 只经 Tailnet 连接 VPS；真实 SFTP 联调 | FS-01 至 FS-13、HB-08、HB-09、HB-11 |
| B4 | 端到端隐私验收中的本机部分 | PV-01、PV-02，以及 PV-03 和 PV-05 的配合 |

## C. 需要经用户交回 VPS 的信息（全部脱敏）

1. 硬件摘要：GPU 型号、显存、可分给 Worker 的 CPU、内存和磁盘额度、驱动版本。
2. 执行环境的选择及小样结论。
3. MX-01 的结构摘要，以及工具链登记信息（`toolchain_id`、浏览器和 ffmpeg 的版本及可执行文件哈希）。
4. P1 的结果：关键帧和联系表 PNG（只限由渲染帧生成的图片），以及 GPU 证据摘要。
5. 部署阶段再提供：Worker 公钥。
