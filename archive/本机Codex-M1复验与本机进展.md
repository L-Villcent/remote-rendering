# 本机 Codex：VPS M1 复验与本机进展

日期：2026-10-08  
范围：离线复验及本机协议校验入口；未部署，未连接 VPS，未生成密钥。

## 1. r5.1 补丁决定

接受 D1、D2、D3 纳入 r5 正式实现基线，版本为 r5.1。

- D1：补充 ingest 读取任务与取消请求，以及 publish 读取任务视图的权限，属于真实运行依赖。
- D2：handoff_record 补齐报告交接的确认消息。
- D3：无法解析且未知尝试编号时允许 conflict 的 attempt_no 为 null，避免编造编号。Worker 将这种确认视为异常交付结论，不视为执行成功。

不重新启动设计评审。后续发现的实际缺陷继续按复现与回归测试流程处理。

## 2. 本机复验情况

SHA256SUMS 覆盖的 77 个文件全部匹配，交接原件未修改。

| 组 | 通过 | 跳过 | 出错 | 说明 |
|---|---:|---:|---:|---|
| SCHEMA | 0 | 6 | 0 | 本机没有 jsonschema |
| SEMANTIC | 22 | 0 | 0 | 基线语义通过 |
| STATE MACHINE | 34 | 0 | 0 | 基线状态机通过 |
| SIM-LIB | 14 | 2 | 3 | 缺少 jsonschema 差分依赖和可发现 ffmpeg；快照测试依赖 Linux |
| SIM-E2E | 0 | 0 | 17 | Linux 原子文件接口在 Windows 不存在 |

完整入口退出码为非零，不能声称本机 98 项全部通过。第一次还遇到当前沙箱临时目录权限问题，改用工作区内的测试临时目录后，剩余错误明确为平台问题，包括 os.O_CLOEXEC、O_DIRECTORY、dir_fd 及 POSIX 所有者等。未将其伪装成通过，也未用常量替换弱化 Linux 快照的安全属性。

VPS 的 Linux 实现继续在 Linux 环境验收；Windows Worker 仅复用平台无关协议和检查逻辑，文件安全操作单独实现。建议测试入口标明 Linux 限定组，并提供可移植组入口，避免“本机应全通过”的误解。这不阻塞 r5.1 确认和模拟开发。

SIM-LIB 的 SL01 已在本机通过，说明 MiniSchema 对交接样例及现有反例可运行；这不等于本机独立复验了与 jsonschema 的差分测试，也不等于完整 JSON Schema 2020-12 实现。

## 3. 已完成的本机工作

已建立独立的本机离线协议校验入口，复用包内严格解析、MiniSchema、语义和文本规则，不导入 Linux 快照代码。结果与状态必须携带关联任务定义；输出仅固定错误码。

新增四项本机测试全部通过：各类交接样例校验、缺少任务定义不跳过语义、拒绝额外命令及联网策略、合成敏感值不回显。这是 Worker 前置组件，不是完整 Worker，尚无执行任务包或网络能力。

硬件受控查询成功：NVIDIA GeForce RTX 4060 Ti，显存 8188 MiB，驱动 610.74。发现 Chrome 和 Edge 可执行文件（主版本分别为 150 和 154）。这些信息只证明工具存在，尚未证明实际 WebGL GPU 渲染、隔离或可复现导出。

Windows 原生仍是优先测试候选，尚未建立独立非管理员 Worker 账户；不把日常账户下的小样当作隔离验收。CPU、RAM 和可分配额度尚未核实，工具链尚未登记。

## 4. 后续分工

VPS 方可按原计划继续 M2：只编写部署脚本、探测程序、缓存及指标，不执行系统变更。无需等待本机为 Linux 代码提供虚假的 Windows 全通过结果。

本机下一步是持久账本、互斥与目录传输模拟，再实现确定性的 WebGL 帧导出和固定编码。GPU 证据、样例矩阵、P1 成品和工具链登记将独立交付，当前均未完成。

独立账户、安装或系统级网络限制、密钥和真实 SFTP 接入在用户授权的部署阶段执行。隐私前提保持：本机公网 IP 不通过连接或内容进入 Anthropic；交接材料统一称本机，不披露地区或真实端点。
