## 2. 冻结前需要修正的协议问题

### R1 幂等身份必须包含任务包

protocol 6.2 仅写按 submission_sha256 比较；submission schema 本身没有任务包哈希。因此同一 submission JSON 配上不同源码包是否冲突没有唯一答案。

请明确定义摘要算法和覆盖范围：例如规范化 submission（明确是否包含幂等键）加 bundle.sha256，并使用固定编码和字段排序规则。不要依赖不同语言的默认 JSON 序列化。测试同键同参数但源码包不同必定 conflict；同键内容一致返回原任务。若 tar 的时间、顺序等影响字节，明确采用字节级身份还是可复现打包。

### R2 未启动或启动失败需要能诚实上报

result schema 对所有 outcome 都要求 browser.major、encoder.version、gpu_model、software_fallback 和 gpu_busy_observed。任务在下载校验失败、启动前取消、浏览器不存在时，这些信息可能未知，不能要求 Worker 编造版本或把“未知”写成 false。

请按阶段和 outcome 定义可缺省或 null 的观测字段，保留成功结果的必要证据；明确 exit_code 如何表达尚未启动和 Windows 原生进程的退出码，当前正负 255 范围无法直接容纳所有原生码。补充提前取消、缺浏览器、下载失败和 GPU 查询不可用的合法结果样例。

### R3 接收失败与取消竞争必须有终态

protocol 5.2 只在结果 accepted 时生成终态，但 6.8 收到 quarantined 后 Worker 会清理并标记交付。此时 VPS 任务可能永久停在 uploading；rejected 重传耗尽也没有对应最终任务状态。较晚取消一个已成功任务也可能被 cancel_requested 覆盖。

请区分执行状态、交付状态和隐私检查结论，定义 quarantined、重传耗尽如何结束显示及通知；明确终态与取消竞争的优先级，终态不可倒退；明确同一 attempt_no 出现不同 attempt_id 时拒绝冲突，以及状态不得以更高 seq 从终态退回 running。补充这些状态机测试。

### R4 补齐 Worker 实际需要读取的接口和语义规则

当前三份 schema 没有完整定义取消请求、结果确认、心跳确认、发布回执及 inbox 视图。请提供固定字段、版本和样例，可放在现有 $defs，不必为了数量增加文件。

明确跨字段校验清单及负责端：job 与结果的 bundle/adapter 绑定、阶段与 profile 配对、产物 ID 唯一、kind/media_type/profile 对应、成功时必需产物与帧数、attempt_no 不超任务上限、progress 不超总量、预览时长上限。部分约束在 schema 注释中提及，但正文没有完整规则或测试。

还需把下载及上传重试次数的 N 落成数值或明确配置项，区分传输重试与执行 max_attempts；final_delivery=upload 的大小政策要与 MP4 检查上限一致。本地保留正式视频的大小不应套用上传限额。Windows 解包要拒绝保留设备名、尾点/空格以及大小写冲突等路径别名，不能仅依赖 Linux 的路径校验。

## 3. 不阻塞主体方向、但实现前需改正的细节

### 媒体结构规则

- PNG 长度和类型头是 8 字节，CRC 是载荷之后的 4 字节。可按每块总结构开销 12 字节计预算，但不能把它写成连续的 12 字节头之后再跳过完整载荷与 CRC，否则解析位置错误。
- 结构指纹应是允许的结构规则和重复次数范围，不是单个样例的精确类型序列。不同合法图片的 IDAT 数量、不同视频的 sample 表会变化；增加同一配置下多个分辨率、时长及复杂度的正例。
- MX-04 不能要求“编码器版本变化必然被结构检查发现”。不同版本可能生成相同结构。工具链变更由受控版本登记与 Worker 报告触发重新验证，结构检查只能捕获实际结构差异。
- 浏览器仅上报 major 无法区分补丁更新。建议登记完整构建的受控标识或工具二进制哈希，避免靠自由文本版本号，同时无需把系统路径写出。

### 文本规则与报告可用性

- TX-TAILNET 若对提到 DERP 或 tailscale status 的任何文字一律拦截，会阻断正常设计报告。区分原始诊断内容和允许的固定术语，不因为讨论检测规则就泄露诊断。
- 四段版本号与地址样式可能相同：应明确只允许已登记版本字段，不让任意日志中的四段数字豁免。TX-03 与正文需要一致。
- 未知 JSON 键不得原样拼入隔离通知的 JSON Pointer；使用 schema_invalid 和固定引用，否则键名仍可携带敏感文本。

### 身份与时序

- Worker 的 attempt_id 使用 ULID 会编码墙钟时间，与“Worker 不发送任何墙钟时间”的字面要求不一致。可改为不含时间的随机标识；若保留 ULID，应明确它是 UTC 时间且不是地区信息，不要同时声称完全没有墙钟信息。
- 心跳 seq 与状态 seq 的作用域不同，接收算法分别描述；Worker 重启后续传同一 attempt 的 seq 如何恢复必须明确。

### 部署与验收表述

- MaxSessions 限制单条 SSH 连接的会话数，不等于账户总连接数限制；不能据此声称只能建立两条连接。MaxStartups 也不是为某用户预留连接的机制。
- inbox 父目录仅允许 render-claude 组遍历，而各服务的写入目标位于其下；请明确服务的祖先目录遍历 ACL，避免子目录属主正确但服务到不了子目录。outbox 的祖先目录同样检查。
- 发布服务需要安全读取 Claude 可写的 outbox：拒绝符号链接、特殊文件和路径竞争后再取快照，不能只有 ingest 对上传做此约束。
- 沙箱内会话的命令不应有绕过沙箱的执行入口。安全文档“! 输出不受沙箱约束”需改为明确实际边界：工具输出仍会进入会话，但正常工具执行应处于沙箱内；若某入口在宿主执行，必须禁用。
- 固定镜像容量和空间回收控制在部署时验证即可。巡检发现空间缺口先告警并检查根分区余量，不应盲目自动补齐而占满根分区。
